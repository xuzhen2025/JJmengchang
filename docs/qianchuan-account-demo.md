# 千川广告账户管理演示验收

更新时间：2026-09-28。仅一期原型，不扩展巨量广告业务。

## 边界

- 所有授权确认、回调校验、账户列表、同步结果均为本地模拟。没有真实登录、Token、授权码交换、千川请求或资金消耗。
- 平台授权与本地接入是两步。拒绝、失败、取消、无账户返回均不接入账户；成功返回后仍需显式勾选并确认。
- 授权主体（店铺/代理商）不是实际广告账户。本地候选列表表示由授权主体关系解析出的广告账户，不是直接拿主体 ID 投放。
- 解除接入仅停用本平台对账户的后续使用，不撤销主体 Token，也不暂停或删除千川已有广告。历史、计划、账户分组、绑定与备注保留。
- 本次完善的是账户管理演示闭环，不代表生产接口已联调验收，也不包含计划日常调价、预算调整等新的管理模块。

## 演示主路径

1. 用登录页的原型账号选择器选择超级管理员，切换管理端，进入「系统管理 → 广告主管理 → 巨量千川」。
2. 点击「去授权」，选择「授权成功」，点击「前往模拟授权」。模拟千川侧展示应用、业务范围、返回平台，不提供真实账号密码输入框。
3. 点击「同意授权并返回」，经过返回校验，选择实际广告账户。默认不选，已有效接入的账户不可重复导入，未选择的账户不会被解除。
4. 确认接入后返回列表。新账户默认绑定接入人且不加入账户分组，不创建任何推送任务或计划。
5. 勾选账户进行批量绑定：小组、分类、用户可独立修改；「保持不变」与「清除关联」是不同动作。可为账户填写备注。
6. 在「账户分组」新增/编辑分组，选入账户，配置可见部门、小组、用户。系统可见性与分组范围取交集，多个可见主体取并集。未限制任何主体的分组仍按原规则向系统范围内全部成员开放。
7. 在「人员账号管理」可找到「普通用户」（工号 DEMO-001），对应现有登录账号 `putongyonghu`。默认部门为电商投放一部、分组为女装千川放量组、角色为普通员工；成员角色和组织归属均可在现有管理页面修改。
8. 在「角色与权限矩阵」给该成员的角色勾选「推送广告账户」。仅推送只需该权限；新建/追加计划还需「管理投放计划」。普通员工默认不自动获得投放权限，已有自定义角色不会被自动扩权。
9. 退出后以普通用户登录，在「资源库 → 成片详情 → 推送广告账户 → 个人账户/全部账户/公司分组」选择被分配且有可见权限的千川账户，提交演示任务。在同一成片的推送记录中查看结果及操作人。
10. 回到管理端可手动同步、查看失效账户并重新授权，或解除接入后重新接入同一账户。恢复不会重新创建已完成的推送任务或开启已有计划。

## 异常与恢复

| 情况 | 可复现入口 | 预期 |
| --- | --- | --- |
| 拒绝授权 | 模拟千川确认页 → 拒绝授权 | 返回拒绝结果，可重新发起；账户不变 |
| 授权服务失败 | 模拟返回结果 → 授权服务失败 | 不接入，保留重试和关闭 |
| 无账户可接入 | 模拟返回结果 → 无可接入账户 | 空结果，确认接入禁用 |
| 回调失败 | 模拟返回结果 → 回调校验失败 | 中止接入，不直接显示账户选择 |
| 恢复了错误账户 | 重新授权/接入 → 未返回待恢复账户 | 阻止确认，原账户及历史不变 |
| 取消等待 | 回调/接入等待时取消或关闭 | 清理模拟定时器，不在关闭后悄悄接入 |
| 重复、过期、身份变化 | 提交前重新校验 | 五分钟演示结果有效期；当前管理权限、身份、账户状态与候选范围再次校验，失败整批不接入 |
| 同步请求失败 | 模拟同步 → 请求失败 → 手动同步 | 保留上次数据与成功同步时间，结果页可重试失败项 |
| 授权失效 | 模拟同步 → 授权失效 → 确认模拟 | 影响所选账户及其相同主体下已接入账户；本地解除的账户不自动恢复；结果页可前往重新授权 |
| 普通同步失效账户 | 已失效 → 手动同步 | 不能伪装成授权恢复，必须重新授权确认 |
| 无功能权限 | 普通员工不配置推送权限 | 入口保留，点击反馈暂无推送权限；禁用成员/角色同样不授予执行权限 |
| 可见范围不匹配 | 修改分组或系统可见性 | 账户不能越权使用；无可选账户保持现有空列表规则 |
| 解除时存在执行任务 | 勾选有真实演示执行中任务的账户 → 解除接入 | 阻止解除，先处理进行中的任务；不停止千川广告 |
| 解除与重新接入 | 已解除接入 → 重新接入 | 只恢复选择账户，保留原配置和历史，不自动投放 |

手动同步默认处理当前平台的已接入账户；勾选后仅处理所选账户。授权失效场景会明确确认相同授权主体的连带影响。恢复某个账户只根据本次已返回并被确认的账户更新，未获确认的账户保留原状态。

## 数据与兼容

- 配置键继续使用 `uc_finished_ad_push`；旧 `uc_ad_push` 迁移到该键，执行层保留兼容别名。`uc_ad_plan_manage` 为原有独立业务权限补齐矩阵入口，不新增管理员授权权限。
- 普通运营按关联成员的多个启用角色取权限并集，不再统一假设普通员工角色；停用/删除成员后不能执行推送。类别范围来自本人或本组已绑定广告账户的本地分类，仍需与分组范围取交集。
- 演示成员仅补入一次。后续改名、换角色、停用或删除均保留，不清空现有本地存储。
- 账户名称、ID、类型、主体关系是模拟千川返回；小组、分类、用户、备注、账户分组及角色权限是本平台配置，不能当作千川返回字段。
- 授权失败和同步失败分别建模，不能将网络失败当作授权失效，不能将本地接入当作素材已上传或广告已投放。

## 真实研发仍需验收

接口依据沿用 `qianchuan-push-api-audit.md` 的 Q22、Q25、Q26、Q27 及相关证据。原型的业务范围文字不是正式 OAuth scope 枚举，模拟成功不验证生产回调。

真实接入必须由后端验证回调与绑定租户/发起人、交换并加密保存 Token、刷新授权、按主体分页解析广告账户并去重、检查应用及账户权限、核查重新授权覆盖范围、处理限流/超时/重试及审计记录。不能将前端演示结果、固定五分钟有效期或硬编码候选账户直接用作生产授权依据。真实授权有效期及共享影响范围以接口返回和服务端授权关系为准。

以上生产工作需使用已获批准的应用及测试账户联调，不能仅凭原型宣称已经与千川实际投放闭环一致。
