# 用户端权限按菜单/按钮两级生效，缺失分别隐藏与提示

权限树不再只是配置展示：菜单权限决定入口是否可见，按钮权限决定操作是否可用，两者分别独立校验。权限读取与广告身份同源（同一会话、角色矩阵与组织成员），角色目录为空时回退内置默认角色，保证普通用户登录即有默认权限。

## 背景与问题

原权限树 52 个叶子权限仅 3 个有局部业务校验（推送、计划、衍生），其余只保存在配置中，取消权限不影响任何入口或操作。产品确认的目标行为是：没有权限的菜单直接隐藏，没有权限的按钮点击提示“暂无权限”，恢复权限后立即生效，详情与间接入口不能绕过。

## 决策

1. **两级权限模型**：菜单权限（侧边栏入口、页签、子页面）缺失→隐藏；按钮权限（修改、下载、删除、推送、导出等具体操作）缺失→点击提示“暂无权限”。
2. **权限树重构**：成片管理 12 项平级（“衍生视频并推送”与“推送广告账户”勾选联动，“衍生新视频”同级独立，无“衍生视频”父级）；删除非按钮项“管理投放计划/查看互动数据/修改工程文件访问权限/查看素材数据/查看引用数据（成片/素材/第三方 3 处）”；数据分析重构为三层（视频数据分析→广告平台分析/广告平台标签/标签分析各含导出；广告账户分析→广告账户数据含导出/投放状态报表无导出；操作记录→7 子页+导出按钮）。
3. **统一权限读取**：`readUserPermissionKeys` 与 `getAdActor` 同源读取（会话 `mengchang_prototype_session`、角色 `cloud_video_roles_v2`、成员 `readReportOrganization`）；`useUserPermissions` 用 `useSyncExternalStore` 订阅权限/组织/广告变更事件，配置保存后界面立即刷新。
4. **角色默认勾选**：普通员工=爆款复刻+资源库 6 查看+操作记录（父级+7 子页），不勾数据分析；角色目录为空时回退内置 `INITIAL_ROLES`，未进过管理端也能获得默认权限。
5. **共享详情弹窗按资源前缀校验**：成片/素材/第三方共用 `FinishedVideoDetailModal`，按钮权限键按资源范围（`uc_finished_*`/`uc_material_*`/`uc_third_party_*`）切换。

## 备选方案

- **仅在提交层校验**：保留菜单可见，只在动作提交时拦截。不符合“隐藏无权限菜单”的产品要求，且入口可见会造成误导。
- **为每个按钮维护独立启用/禁用状态**：需要为每个按钮增加禁用态 UI 与文案，改动面大；原型要求统一为点击提示“暂无权限”。
- **沿用局部校验（推送/计划/衍生）**：无法覆盖其余 50+ 叶子权限，审计项 AUTH-01 不闭环。

## 后果

- 权限配置保存后立即影响菜单与按钮，无需刷新或重新登录。
- 管理端改权限后，用户端同一会话内的页面在下次点击/事件时刷新权限缓存。
- 非按钮勾选项（原权限树中已删除的 6 项）不再出现在权限树，由产品后续在配置界面清理遗留数据。
- 新页面新增操作按钮时，必须按两级模型补充对应权限键与校验，否则默认无校验（延续原型既有行为，待后续统一收敛）。
